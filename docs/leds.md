# 智能状态灯

[返回项目首页](../README.md) · [系统维护](maintenance.md) · [验收记录](development-status.md)

页面按设备实际枚举的 `/sys/class/leds/*/trigger` 提供 Linux 内核 LED 触发器。选择网卡、Wi‑Fi、存储或系统触发器后，由内核在对应事件发生时直接更新灯效；不创建 LED cron 任务，也不启动常驻轮询进程。

常见触发器包括：

| 触发器                   | 用途                                           |
| ------------------------ | ---------------------------------------------- |
| `netdev`                 | 按所选网络接口的链路、接收和发送活动控制指示灯 |
| `phy*rx`、`phy*tx`       | 显示无线收发活动                               |
| `phy*assoc`、`phy*radio` | 显示无线关联或射频开关状态                     |
| `heartbeat`              | 显示系统心跳                                   |
| `mmc0`                   | 显示存储活动                                   |
| `timer`                  | 按指定亮灭时间闪烁                             |
| `default-on`             | 使用内核常亮触发器                             |

不同固件和设备支持的触发器不同，页面只显示驱动实际提供的选项。AX1800 和 N1 均通过运行时能力枚举，不硬编码灯的颜色或触发器。N1 单色灯可选择其驱动支持的触发器；驱动若没有 `timer`，就不能用它闪烁。

`netdev` 只反映所选 Linux 网络接口的链路和数据收发，不判断公网在线或离线。需要公网连通性判断时，必须另行运行 ping 监测；本功能按要求不做此类检测。

开机灯效由 START=11 的一次性脚本设置，系统启动到 START=99 后切换到所选内核触发器。接口 hotplug 只在接口变化时重新应用设置，作为设备名尚未就绪时的补充；不做周期检查。保存配置后立即应用；停用或卸载时尝试恢复接管前的触发器、亮度和参数。新版不会创建或清理旧版指示灯 cron 行；升级后如仍有 `# router-ui-led` 行，请手动从 `/etc/crontabs/root` 删除该行。

仅接管用户明确配置的指示灯；“保持设备原有灯效”不会修改该灯。配置保存在 `/etc/router-ui-led.json`，系统归档会包含它；网络 JSON 备份不包含灯效。灯效保存不会修改网络配置，也不触发网络回滚。

内核触发器的具体灯色、节奏及硬件连线由设备树和 LED 驱动决定。软件页面可以读取能力并配置触发器，但真实灯效仍需在 AX1800、N1 等设备上检查。
