# 状态指示灯

[返回项目首页](../README.md) · [系统维护](maintenance.md) · [验收记录](development-status.md)

在侧栏“指示灯设置”（`/settings/leds/`）启用“按系统状态控制指示灯”。为开机、正常、断网、故障分别选择实际可用的灯，以及常亮、熄灭或闪烁；闪烁的亮起和熄灭时间可分别设置为 50–10000 毫秒。

AX1800 当前固定源码定义红、绿、蓝三路状态灯，N1 上游设备树定义白色状态灯。页面最终以运行中 `/sys/class/leds/` 的实际枚举和 timer 触发器为准，不虚构不存在的颜色。默认建议：开机蓝灯 250/250 毫秒闪烁、正常绿灯常亮、断网红灯 1000/1000 毫秒闪烁、故障红灯 100/100 毫秒闪烁。N1 可用同一盏白灯的不同节奏区分状态。驱动未提供 timer 时只能选择常亮或熄灭。

| 状态 | 判断方式                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 开机 | 用户空间 START=11 的一次性启动脚本开始，到 START=99 完成检查之前；更早的引导和救援模式由固件原有逻辑控制 |
| 故障 | `netifd`、`rpcd`、`uhttpd` 中任一个关键进程缺失，优先于断网状态                                          |
| 断网 | 关键进程存在，但两个配置目标均无法响应 ping                                                              |
| 正常 | 关键进程存在，至少一个配置目标能响应 ping                                                                |

默认探测目标为 `223.5.5.5` 和 `119.29.29.29`，可改为自己认可的 1–2 个单播 IPv4 地址。检测使用系统已有 cron 每分钟执行，接口 ifup/ifdown/ifupdate 时也会更新，单次最多探测两个目标，每个等待 2 秒。ICMP 被拦截可能误判；将目标设置成网关只能证明网关可达。这个状态不能代表所有互联网服务正常，也不能检测断电、内核崩溃、进程卡死或全部业务异常。

配置默认关闭，关闭时不发送探测流量。启用后只接管四个状态中选中的灯，状态切换时先熄灭这些灯，再应用当前灯效。停用后尝试恢复接管前的触发器和亮度，并删除本功能的 cron 行，保留其他任务。配置原子保存于 `/etc/router-ui-led.json`，系统归档会包含它；网络 JSON 备份不包含灯效。没有网络设置的 120 秒回滚，因为保存不修改网络配置。

运行时由两个一次性启动脚本、接口 hotplug 和已有 cron 驱动，没有新增常驻进程。cron 停用时启用此功能会启用并启动系统 cron；关闭指示灯功能不会停止其他任务共用的 cron 服务。暂存、待确认网络配置或其他维护操作期间拒绝保存；周期检测会避开维护锁。

页面会检查本功能的 cron 标记行和 cron 服务状态。启用状态控制时若每分钟检查任务缺失、重复或被改动，页面提供重新同步；关闭状态控制时若发现残留标记行，可从页面清理。修复只重建或移除指示灯自己的标记行，并保留其他 cron 任务。

QEMU 不模拟物理灯。测试在隔离目录验证四种状态、闪烁参数、原灯效恢复、禁用后不探测和保留其他 cron 任务，同时在真实 OpenWrt 检查接口权限、无硬件限制和启动钩子安装。物理灯颜色、驱动触发器和开机时序仍需 AX1800/N1 实机验收。
