原计划是在自研配置和恢复能力完成后再移除 LuCI。当前轻量配置提前做了裁剪，这部分进度不能等同于第五阶段完成。正式使用前需完成前三阶段的镜像与实机验收，并验证第四阶段的配置恢复。

后续先完成镜像编译与 USB/实机验收，验证网络备份恢复，再增加无线运行状态和需要的单项旁路服务。每项服务单独核对包依赖、固件体积与运行内存，保持默认系统轻量。

验收记录：[源码配置检查 #40308195152](https://github.com/Guccen/openwrt-cli/actions/runs/40308195152) 中三种模式全部通过；Artifact 保存实际源码提交、解析配置及日志。本地 19 项前端测试、14 项固件脚本测试，以及双端口模拟的跨来源页面交接测试通过。双端口测试只验证浏览器会话交接，真实 LAN 地址变化仍由 QEMU 测试和实机验收覆盖。

[完整构建 #40317233994](https://github.com/Guccen/openwrt-cli/actions/runs/40317233994) 的三个前置模拟任务已全部通过，包括 DNS 确认/恢复、不同会话权限、会话结束后回滚、LAN 改址超时恢复，以及首次导航失败后的页面重试与跨地址确认。AX1800 构建任务已成功，Artifact `jdcloud-ax1800-router-3` 包含 factory 15,443,265 字节、sysupgrade 14,663,953 字节和 `router-ui-0.2.0-r1.apk`。下载后逐项核对 SHA-256 通过，实际 APK 再次通过 QEMU 安装及功能测试。此结果对应 `f89f89a` 基线，不代表 0.4 新增功能已进入该镜像。N1 首轮编译已执行到生成校验和，随后因根文件系统匹配规则失败，未进入 ophub 打包；修复后重新构建。

0.3 网络备份恢复使用现有 UCI ACL，未增加后台服务、任意命令或文件写接口；只保存支持的 LAN、DNS 和 AP 字段，WiFi 密钥以明文保存在客户端文件中。同时增加 wouter History 路由，页面、主布局和设置表单分别拆分；生成静态页面入口供 uhttpd 直接访问。当前本地 28 项前端测试、14 项脚本测试通过，桌面/平板/手机浏览器检查共 16 项通过、2 项按范围跳过；增加路由后，首次导航失败的双端口跨来源会话交接也通过复测。GitHub 对本次新增路由、备份及多配置回滚的验收仍待运行结果。

0.3 首次模拟发现切页后的迟到配置读取会清空刚选择的备份。`2981496` 修复为新页面等待读取完成后才开放表单，回归测试对 UCI 响应增加延迟。修复后的 N1 旁路由和 AX1800 模拟已通过，N1 主路由仍以运行结果为准。

0.4 新增独立 `/wireless/` 与 `/system/` 页面，按子组件拆分。无线状态仅允许读取，iwinfo 依赖只加入 AX1800 正式固件。系统配置归档最大 128 KiB，使用标准备份列表，前后端校验体积和 SHA-256；重启和导出都检查全会话暂存/待确认状态，维护操作串行执行。未开放文件上传、任意命令、在线刷机或恢复出厂。维护操作期间请停止其他窗口或 SSH 的配置修改，原生 UCI 与维护接口没有跨接口原子锁。

新增 QEMU 验收会检查匿名访问、跨会话暂存拦截、待确认配置拦截、归档校验及清理，并通过维护接口真实重启，比较 boot ID、配置和旧会话。含测试密钥的系统归档不会进入 Artifact，导出页面测试关闭 trace。本地 34 项前端测试、17 项脚本测试通过。生产静态服务下，22 项浏览器检查先通过；修正新增无线状态用例的异步等待后，三种宽度补测全部通过，另 2 项按范围跳过；双端口跨来源交接复测通过；0.4 的真实设备接口验收等待新的 GitHub 模拟结果。

N1 产物收集改为明确选择 `*-generic-rootfs.tar.gz`，允许上游同时生成目标级根文件系统，且核对归档内的设备/模式/源码版本。数量异常时保存 `target-files.json`，失败任务额外保留原始根文件系统及 APK。新增回归覆盖两份归档并存、缺失、多义及模式不匹配，并关闭无用途的 CPIO 输出。

前端页面按路由延迟加载，主入口 JS 从约 513 kB 降至 348 kB，全部静态文件约 583 KiB、逐文件 gzip 合计约 189 KiB，仍在预算内。首次加载还需要共享模块和 CSS；这不是首屏总传输量。最新 QEMU 的三种宽度系统归档导出已通过，仍需修复无线服务模拟环境和完成维护运行时验收。
