# 系统维护与独立更新

[返回项目首页](../README.md) · [网络设置备份恢复](configuration.md) · [固件构建](firmware-build.md)

## 导出系统配置归档

“系统维护”使用 `router.maintenance` 固定操作插件。导出沿用 `sysupgrade -b` 的标准配置列表，并加入设备、模式、源码提交和固件版本清单；归档最大 128 KiB，临时文件置于私有目录并在结束后删除。客户端验证大小、gzip 标记及 SHA-256 后下载。归档可能包含密码哈希及私钥，不是完整磁盘备份，也不包含 N1 引导分区。

## 恢复系统配置归档

选择 0.6 或更新版本导出的 `.tar.gz`，点击“上传并校验”。设备重新核对 SHA-256，解压上限 2 MiB，最多 512 个成员，验证 tar 头校验和与结束块。只接受 `etc/` 下的常规文件和目录，拒绝路径穿越、重复路径、软硬链接、设备节点和其他扩展成员；同时拒绝设备端已有符号链接路径。含这些成员的自定义归档请通过 SSH 检查后处理。

网页恢复要求清单中的设备、主/旁路模式、源码提交和完整固件版本与当前系统一致。旧归档缺少清单时不会直接写入；仍可按 OpenWrt 标准通过 SSH 检查恢复。清单与 SHA-256 用于一致性校验，不证明备份来源可信。

校验完成后显示归档体积、成员数和 SHA-256。输入“恢复系统配置”并确认后，设备再次校验，使用 `sysupgrade -r` 恢复经检查的配置并重启；清单不会写入系统根目录。恢复前额外生成临时救援备份，写入失败时尝试恢复原配置并返回错误。此过程不提供网络设置的 120 秒回滚，也不保证断电或磁盘故障时的原子恢复。

恢复会覆盖归档中的密码和网络配置，请记录备份时的管理地址并保持有线连接。取消会删除临时文件；离开页面也会尝试取消。未完成上传在最后一块数据写入后 10 分钟失效，下次维护上传请求清理过期文件，重启也会清空 `/tmp`。

## AX1800 固件升级与恢复出厂

网页升级使用浏览器上传本地固件，不接受 URL，不自动下载或刷写远程最新版。选择匹配设备的 `*-sysupgrade.bin`，填写构建产物 `sha256sums` 中对应的 SHA-256。客户端先校验摘要，再以 32 KiB 分块上传；最大 32 MiB，临时空间至少需要 40 MiB。设备在预览和最终执行时重新核对完整摘要并运行 `sysupgrade -T`。输入“升级固件”后通过 `sysupgrade -n` 刷写，清除旧配置，不开放强制刷写。全过程保持供电并使用网线。

恢复出厂仅在真实 AX1800 板型、squashfs `/rom` 和可写 overlay 根文件系统同时满足时开放，输入“恢复出厂设置”后执行 `jffs2reset -y` 并重启。恢复的是当前固件默认配置，不能退回原厂固件。升级与重置后的默认管理地址取决于刷入的固件；本项目 AX1800 默认 `192.168.68.1`。

设备端使用真实板型门禁，不依赖前端的 `device.json`。N1 和 generic/ext4 虚拟机拒绝网页升级与恢复出厂；N1 按[刷机步骤](flashing.md)重新写入启动卡。AX1800 的真实闪存写入与恢复出厂仍需实机验收。

## 重启设备

重启需要页面二次确认，后台只调用固定的 `system.reboot`，不接受命令或路径。后台检查所有 rpcd 会话的暂存差异及回滚快照，并在执行前再次检查；备份和重启通过互斥目录串行执行。请在维护期间停止其他窗口或 SSH 的配置修改；这些操作与 OpenWrt 原生 UCI 接口不构成原子事务。重启后页面短时探测设备，原会话失效后返回登录页。演示接口不会备份宿主机或执行重启。

## 修改登录密码

“系统维护 → 修改登录密码”修改设备的 `root` 密码，同时影响网页和后续 SSH 密码登录。填写当前密码、新密码及确认密码，新密码需要 8–128 字节，不能全为空白、包含控制字符或与当前密码相同。设备端重新验证当前密码，并固定通过 `passwd root` 的标准输入设置新密码；不允许客户端选择用户名、命令或文件，也不把密码放入命令行参数、URL、日志和浏览器存储。

存在暂存或待确认网络配置时拒绝修改密码。成功后清理所有已有 root 网页会话，并返回登录页使用新密码登录；已经建立的 SSH 连接不因此中断。若旧网页会话清理失败，登录页会提示重启设备；请求因断网丢失时先尝试新密码登录，避免重复提交。首次安装或恢复出厂后仍先通过 SSH 执行 `passwd` 初始化密码。

## 独立更新前端包

`router-ui` 0.7.0 可单独更新静态资源、ACL 和维护插件，安装后重启 rpcd，刷新页面并重新登录以取得新接口和权限。AX1800 的无线运行详情还需要安装固件来源匹配的 `rpcd-mod-iwinfo`。仅使用自己构建且已核对 SHA-256 的包，在没有暂存或待确认配置时更新，例如：

```sh
scp -O router-ui-0.7.0-r1.apk root@192.168.68.1:/tmp/router-ui.apk
ssh root@192.168.68.1 'apk add --allow-untrusted /tmp/router-ui.apk && /etc/init.d/rpcd restart'
```

安装包不改变设备网络默认值；默认配置变化仍需重新构建固件或通过设置页面修改。
