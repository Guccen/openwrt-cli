# 刷机步骤（AX1800 / N1）

[返回项目首页](../README.md) · [设备接线与初始化](getting-started.md) · [固件构建](firmware-build.md)

## 适用前提

本文档假设两台设备**已经刷过第三方 OpenWrt**（别人构建的镜像），现在要换成本项目的镜像。
如果你手里的还是原厂固件，本文档不覆盖原厂刷机流程，先按原厂方式刷入 OpenWrt 再回来。

先说结论，免得走弯路：

| 设备 | 本次是升级还是全新刷 | 用哪个文件 | 旧配置保留吗 |
| ---- | -------------------- | ---------- | ------------ |
| AX1800 / RE-SS-01 | 直接升级，用 sysupgrade 镜像 | `*-squashfs-sysupgrade.bin` | 不保留，换构建后用全新配置 |
| N1（旁路由 / 主路由） | 没有“在原系统上升級”这个概念，每次都是把完整镜像写到卡上 | `phicomm-n1-模式-k版本.img.gz` | 不适用，写卡即全新系统；旧卡留着就是回滚 |

两条路径都不动引导：AX1800 的 sysupgrade 只写系统分区，不动 bootloader；N1 写卡只动外置卡，不动 eMMC 和引导。
所以只要文件没下错、刷机过程不断电，“连引导都进不去”的真砖本来就很难发生；
真正的风险是“刷完进不去系统、配置错乱”，而那都有回滚路径，见文末。

另有一点必须先说明：本项目 0.5 镜像已通过 CI 的模拟与完整构建，
但按[开发进度](development-status.md)，真机启动、WiFi、交换机、NSS（AX1800）与 USB 启动、网卡、存储、重启（N1）的实机验收尚未完成。
也就是说，**你第一次实机刷入本身就是一次验收**，务必按下面“刷前准备”备好回滚再动手。

## 产物与文件对照

从 GitHub Actions 的“Build lightweight firmware”运行里下载对应 Artifact（名字里的数字是构建运行编号，每次会变）：

| Artifact | 里面的关键文件 | 用途 |
| -------- | -------------- | ---- |
| `jdcloud-ax1800-router-<编号>` | `libwrt-qualcommax-ipq60xx-jdcloud_re-ss-01-squashfs-sysupgrade.bin`（约 15 MB） | AX1800 从 OpenWrt 升级用，**本次就用它** |
| 同上 | `libwrt-qualcommax-ipq60xx-jdcloud_re-ss-01-squashfs-factory.bin`（约 15 MB） | 给原厂固件/救砖准备的，**已刷 OpenWrt 的机器本次不要用它** |
| 同上 | `sha256sums` | 核对上面两个文件的 SHA-256 |
| `phicomm-n1-bypass-<编号>` | `phicomm-n1-bypass-k6.12.114.img.gz`（约 157 MB） | N1 旁路由的完整启动镜像，写卡用 |
| `phicomm-n1-router-<编号>` | `phicomm-n1-router-k6.12.114.img.gz` | N1 主路由的完整启动镜像，写卡用 |
| 上述 N1 Artifact | `immortalwrt-armsr-armv8-generic-rootfs.tar.gz` | 仅用于再次打包，**不能直接刷入 N1** |

注意：N1 旁路由和主路由是两个不同的镜像文件，下载时按你要的模式选对；
切换 N1 模式时不要保留旧网络配置，见[设备与首次使用](getting-started.md)。

## 刷前准备（两台通用，缺一不可）

1. **核对 SHA-256。**下载后先对一下 Artifact 里 `sha256sums` 的值，值对不上就重新下载，不要往下走。
   下载损坏的镜像是刷机失败最常见、也最容易避免的原因。
2. **备份旧系统配置。**旧系统如果是 LuCI，用“系统 → 备份/升级”导出备份；
   如果只有 SSH，进旧系统执行 `sysupgrade -b /tmp/backup.tar.gz` 再拷出来。
   这份备份是你的后悔药：新系统出问题时，至少旧配置还在。
3. **手抄宽带账号密码。**本项目的网络 JSON 备份不包含 WAN 及宽带账号密码，
   旧系统的备份也不一定包含，换构建又不保留配置，所以拨号账号密码必须另外记下来。
   同时记下旧系统的管理地址、WiFi 名称和密码，刷完要重新填。
4. **一次只动一台，先刷旁路由再刷主路由。**
   N1 旁路由先刷：主路由还在工作，全网不断网，刷机时还能查资料；
   AX1800 主路由最后刷。两台同时断网出问题时最被动。
5. **准备好回滚物。**AX1800：把旧固件文件和第 2 步的备份留在电脑上；
   N1：旧卡不要格式化，留着当回滚盘（见 N1 一节）。

## AX1800：直接 sysupgrade 升级

### 第 1 步：传固件到设备

用网线连 AX1800 的 LAN，把 sysupgrade 文件传到旧系统的 `/tmp/`：

```sh
scp -O libwrt-qualcommax-ipq60xx-jdcloud_re-ss-01-squashfs-sysupgrade.bin root@<旧系统管理地址>:/tmp/sysupgrade.bin
```

再进 SSH 核对一次校验值（和 Artifact 里的 `sha256sums` 对照）：

```sh
ssh root@<旧系统管理地址> 'sha256sum /tmp/sysupgrade.bin'
```

### 第 2 步：二选一刷入，不保留配置

因为换了构建，旧配置（软件包、默认地址、无线、NSS 相关）可能与新镜像冲突，
所以**不要保留配置**，用全新配置起步，刷完再按[设备与首次使用](getting-started.md)重新设置。

- 有 LuCI 的旧系统：系统 → 备份/升级 → 刷写新固件，选中 sysupgrade 文件，
  **取消勾选“保留配置”**，点刷写，等设备自动重启。
- 只有 SSH 的旧系统：

```sh
ssh root@<旧系统管理地址> 'sysupgrade -n /tmp/sysupgrade.bin'
```

`-n` 就是不保留配置。不要用 factory 文件走这一步，也不要在无线连接下刷机。

### 第 3 步：等自动重启，验证

刷机过程**不断电、不拔网线**，等设备自动重启（约一两分钟）。
然后按新系统默认值验证，AX1800 默认管理地址是 `192.168.68.1`：

1. 网线连 LAN，打开 `192.168.68.1`，能进管理页；
2. SSH 登录后先执行 `passwd` 设置自己的 root 密码（仓库不写固定密码）；
3. 无线默认是关闭的，在“无线设置”里填自己的 SSID、加密与密码后启用；
4. 拨号、DHCP、LAN 按[网络配置](configuration.md)逐项核对。

### 回滚

只要还能进系统（网页或 SSH 任一能进），回滚就是再 sysupgrade 一次：
刷回旧固件文件（保留配置与否按旧固件的要求），或重刷本项目镜像。
如果连系统都进不去了，需要走该机型的恢复模式——原厂恢复流程不在本项目文档覆盖范围内，
刷机前请先确认你手头的恢复手段（复位键/恢复模式）可用，不要等到出事再找。

## N1：写卡启动（旁路由 / 主路由通用）

### 第 1 步：把镜像写到一张新卡上，不要动旧卡

N1 没有“在原系统上升級”这回事：每次换镜像，都是把完整 `.img.gz` 写到外置卡/U 盘上再启动。
所以**先准备一张新卡**，旧卡原样留着——旧卡就是你的回滚盘，插回去就能回到旧系统。

1. 下载对应模式的镜像（旁路由用 `phicomm-n1-bypass-*.img.gz`，主路由用 `phicomm-n1-router-*.img.gz`），
   先按 Artifact 里的校验值核对 SHA-256。
2. 用 balenaEtcher 这类带写入后校验的工具把镜像写到新卡（Etcher 可直接选 `.img.gz`，不用先解压）；
   如果用命令行，务必先用 `lsblk` 反复确认目标盘符，`dd` 写错盘会直接毁数据，写完执行 `sync` 再拔卡。
3. 卡启动验证前不要动 eMMC：本项目不自动改引导、不写入 eMMC，默认就是卡启动。

### 第 2 步：插卡启动，验证

1. 旧系统先关机，新卡插入 N1，上电启动。
2. 如果旧系统在 eMMC 里：先这样启动一次验证——能进新系统，说明卡启动优先；
   验证通过之前不要动 eMMC，也不要格式化旧卡。
3. 按模式验证默认地址：旁路由 `192.168.68.2`（需排除出主路由 DHCP 分配范围），
   主路由 `192.168.69.1`；主路由需另接 USB 有线网卡做 WAN（建议 RTL8152/RTL8153，自带网口做 LAN）。
4. SSH 登录后先执行 `passwd` 设置 root 密码，再按[设备与首次使用](getting-started.md)做初始化；
   旁路由的上游网关和 DNS 应指向主路由 `192.168.68.1`，且 DHCP 与 IPv6 通告保持关闭。

### 关于 eMMC

本项目不提供、也不自动执行写 eMMC 步骤。如果你确实想把系统装进 eMMC，
那是超出本文档的手动操作，默认建议一直用卡启动：卡启动本身已够用，且回滚就是换卡。
只有在卡启动长期验证稳定、且你确认 eMMC 写入流程后，再单独处理 eMMC。

### 回滚

插回旧卡、上电，即回到旧系统。就这么简单——这也是 N1 路径最不容易砖的原因。

## 刷后验证清单（两台都过一遍）

- 管理页能打开、SSH 能登录、root 密码已改成自己的；
- WAN 能联网（主路由拨号或 DHCP 上网正常）；
- LAN 内设备能拿到地址、上网正常；
- AX1800：双频 WiFi 按自己设置的 SSID 可见、可连；
- N1 旁路由：主路由 DHCP 范围里没有 `192.168.68.2` 冲突，上游网关/DNS 指向主路由；
- 配置改动后做一次重启，确认重启后配置还在、服务正常。

## 出问题怎么办

| 现象 | 处理 |
| ---- | ---- |
| 校验值对不上 | 重新下载，不要刷 |
| AX1800 刷完进不去管理页 | 先等够重启时间、换网线口、确认电脑拿到 `192.168.68.x` 地址；还不行就按“回滚”一节重刷，或走机型恢复模式 |
| AX1800 刷完配置错乱 | 换构建不保留配置是预期行为，按[设备与首次使用](getting-started.md)重新初始化，不要把旧构建的整份配置直接导进来 |
| N1 新卡启动后没反应 | 先确认镜像文件选对了模式、卡写完整且校验通过；换一张卡/读卡器再试；还不行就插回旧卡确认旧系统正常，再排查新卡 |
| N1 启动后网络不通 | 先按模式核对地址与接线：旁路由看网关/DNS 是否指向主路由、地址是否冲突；主路由看 USB 网口名称（`ip link` 核对，默认 `eth1`）与 WAN 接线 |

## 一句话总结

AX1800 是“sysupgrade 升级包、全新配置”；N1 是“完整镜像写新卡、旧卡留着回滚”。
两条路都不动引导，刷前核对校验值、备好份、一次动一台，砖的风险就已经被掐掉大半。
